# FrameFlow Design Notes (as built)

## Decisions

Resolved during planning (see `docs/TASKS.md`). Where these contradict PRD, SPEC, SRS,
ARCHITECTURE or UIUX, these decisions win.

| ID | Topic | Decision | Supersedes / clarifies |
| --- | --- | --- | --- |
| D1 | Threads | `std::thread` + `std::atomic<bool>` stop flag + join in a destructor. No `std::jthread` (C++20). | SPEC 9.1, ARCHITECTURE 4.3 |
| D2 | Names | Policy hook is `should_drop_on_pop`; metrics class is `MetricsStore`. | ARCHITECTURE 6.2 (`drop_on_pop`), SPEC 9.1 (`MetricsCollector`) |
| D3 | Phase 1 run | The Phase 1 gate (60 s at 30 FPS) is an integration test labelled `long`; `main()` gains a CLI only in Phase 2. | SPEC 16 Phase 1 |
| D4 | Clock vs timeouts | `Clock` is used for every timestamp and for pacing. Queue timeouts use `condition_variable::wait_for` with real durations (steady clock inside the standard library) and are tested with lower bounds only. | CLAUDE.md "steady_clock via Clock" |
| D5 | Bursty seed | `--seed` seeds `std::mt19937`, which picks the first spike's offset in `[0, spike-every)`; spikes then repeat exactly every `spike-every`. | SRS FR-PROC-04 |
| D6 | UIUX extras | `--progress` is in scope (Phase 5). `--json`, `--no-color`/`NO_COLOR`, `--verbose`/`--trace`, short aliases, terminal-width handling and colours are out of scope. | UIUX 3, 10, 11, 12.2; ARCHITECTURE 10 |
| D7 | Python tests | `analyze.py` is tested with pytest (`python3-pytest` from apt); all C++ is tested with GoogleTest. | CLAUDE.md "GoogleTest tests" |
| D8 | Disk full | EC-17 is simulated by writing to `/dev/full`, not a tmpfs (mounting needs root). | SRS EC-17 |
| D9 | Timing tests | The PR-05 cost-accuracy test runs only in the release preset, under ctest label `timing`. | SPEC 15 "never exact timings" |
| D10 | Long tests | 60 s runs, stress and lifecycle tests use ctest labels `long`/`stress`, are excluded from the default run, and run in a separate CI job. | SPEC 15 |
| D11 | Experiments | The developer runs the multi-hour experiments on the reference machine; numbers in RESULTS.md come only from produced output files. | SPEC 11, CLAUDE.md |
| D12 | "Write it myself" tasks | Claude writes the GoogleTest tests first and explains them; the developer writes the code; Claude reviews it. | docs/TASKS.md |
| D13 | Stamping `t_push` | The source stamps `t_push` immediately before calling `push`, while it still owns the frame. `BoundedQueue<T>` stays generic and needs no hook for it. Consequence: `t_push` is the push *attempt* time, so under blocking `t_pop - t_push` includes time spent waiting for space; BR-04 still holds. | SPEC 6.1 step 2 |
| D14 | FakeClock sleeping | `FakeClock::sleep_until(t)` never blocks: it moves fake time to `max(now, t)` and returns, so a test can never hang waiting for someone to advance the clock. Its time is guarded by a `mutable std::mutex` so `now() const` is thread-safe. | Independent review assumption of a blocking fake |
| D15 | Frame move is `noexcept` | `Frame`'s move operations are declared `noexcept = default` even though OpenCV 4.6 does not mark `cv::Mat`'s move `noexcept`. GCC accepts this (P1286R2), and a `cv::Mat` move only swaps pointers and never allocates, so the promise holds; if it ever threw, `std::terminate` would be called. Frames move as `FramePtr` in the pipeline, so this affects only direct `Frame` moves. | Correction of the P1.2 explanation |
| D16 | Sink interface | `ISink::consume(Frame&)` instead of `consume(FramePtr)`: the sink stamps `t_out`, the worker keeps ownership and records the frame, then frees it. One place (the worker) records delivered frames, so frame accounting (BR-01) stays simple. | ARCHITECTURE 6.2 |
| D17 | How a run ends | Every end condition (duration, `--frames` count reached, input end, stop request, thread error) goes through the same shutdown routine. Frames still queued at that moment are recorded as in-flight; the worker does not drain the queue first. With `--frames=N`, N frames are released and the last few are usually in-flight. | SRS FR-CLI-05, BR-01 |
| D18 | Queue item type | `BoundedQueue<T>` stays a class template, but T must be pointer-like with a `meta` (FrameMeta) member (e.g. `FramePtr`), because the policy decides from the incoming frame's metadata. Queue unit tests use a minimal `std::unique_ptr<TestItem>` instead of `int`. | SPEC 9.2 (generic `T`) |
| D19 | What warm-up excludes | Frame counts (produced, delivered, dropped, in-flight) cover the whole run so conservation (BR-01) can be checked against them. Latency percentiles, input/output FPS, drop rates and queue-depth statistics use only frames with `t_cap` (and depth samples with `t`) at or after `t0 + warmup`, over the window `[t0 + warmup, t_end)` (BR-06). Mean depth is the plain mean of the samples taken at every push and pop. | SRS BR-01, BR-06, FR-MET-04; UIUX S4 |
| D20 | `--source=file` before Phase 5 | The default source stays `file` (VR-15), but until the video source exists (P5.1) a file source is rejected with "is not available yet (hint: use --source=synthetic)" instead of failing later. | SRS VR-15, SPEC 16 |
| D21 | Default warm-up vs short runs | VR-04 requires warm-up < run length. An explicit `--warmup` that breaks this is an error; the *default* 3 s warm-up is lowered to 0 for runs of 3 s or less, so `--duration=2` alone is valid. | SRS VR-04 |
| D22 | Hostname hash | `hostname_hash` is FNV-1a 64-bit as 16 lowercase hex digits. It gives privacy by default (the plain hostname never reaches a result file), **not security**: it is not cryptographic, and a common hostname can be recovered by hashing guesses. No new dependency is needed. | SRS DR-08, SR-08 |
| D23 | Git commit | `git rev-parse --short HEAD` runs in CMake at configure time and is compiled into `version.hpp` as `kGitCommit` (`"unknown"` outside a git checkout). It is stale until CMake re-configures after a new commit, and it does not mark uncommitted changes. | SRS FR-CLI-04, BR-10, SR-09 |
| D24 | `summary.json` schema | `schema_version` is `1`. `metrics` is a flat object whose keys are exactly the `RunStats` field names (`produced`, `p95_ms`, `output_fps`, `drop_oldest_pct`, ...); an empty `std::optional` is `null`. `config` holds every `RunConfig` field (resolution as `"WxH"`, `cost_wait` as `"busy"`/`"sleep"`). | SRS DR-04 (key names unspecified) |
| D25 | Extra `summary.json` keys | Besides the DR-04 keys, the top level has `warnings` (array of strings; empty until P2.11 fills it, ER-07), `ended_by` (`duration`, `frames`, `input_eof` (SRS EC-05), `stop_requested`, `error`) and `error` (`null` unless the run ended by error), so the reason for `valid=false` is visible. | SRS DR-04, ER-07, BR-09 |
| D26 | Default `--out` | The default output folder is the first `results/run_NNN` (001, 002, ...) that does not exist, not `results/<timestamp>`: a timestamp needs the wall clock (`system_clock`), and CLAUDE.md allows only `steady_clock` via `Clock`. `results/` is created if missing; an explicit `--out` must have an existing parent (VR-17). | SRS VR-17; UIUX S2/S4 already show `results/run_001` |
| D27 | Run-start block | S2's header is `FrameFlow <version>  ·  run started` without the wall-clock date and time (same reason as D26). The processing line shows `cost <ms> ms (<mode>, <wait>)  ·  overload <cost x fps>x`; there is no `--processor` until Phase 5. | UIUX S2 |
| D28 | CLI parsing | CLI11 stores every flag as a string; `validate()` does all checking so every error is reported at once (VR-23). Unknown flags are collected with `allow_extras()` and each one gets its closest flag by edit distance (VR-21). A missing command is exit 2 with a hint. CLI11 sorts nothing, but nlohmann-json writes `summary.json` keys in alphabetical order. | SRS VR-21, VR-23 |
| D29 | Safety flags | `--overwrite`, `--allow-any-out` and `--allow-root` are boolean flags in the `Output` help group. The root check runs first, before validation, so nothing (not even the output folder) is touched as root without `--allow-root`. The effective UID is a parameter of `run_command` so tests need no root. | SRS FR-ROLE-02, SR-05; UIUX 3 |
| D30 | `--overwrite` meaning | `--overwrite` reuses an existing folder: only FrameFlow's four result files in it are removed (`unlink`, so a symlinked result file loses the link, never its target), then recreated with `O_EXCL`. Other files in the folder are left alone (DR-11). Without it an existing path is exit 4. | SRS BR-12, DR-11, SR-06 |
| D31 | Symlinked `--out` | SR-05 is applied to the whole path: if resolving symlinks anywhere in `--out` (the folder or a parent) changes it, the resolved path must be inside `$HOME` or the current folder (both canonicalised), else exit 4 with a hint for `--allow-any-out`. A plain path with no symlinks may be anywhere the user can write. | SRS SR-05 |
| D32 | Writing result files | Every result file is created with `open(O_CREAT \| O_EXCL \| O_NOFOLLOW, 0644)` and written through that same fd by a small `std::streambuf`, so the file is never reopened by name. Write errors keep the OS reason (`No space left on device`) and the file name (ER-05); disk full is tested by writing to an fd on `/dev/full` (D8). Exit codes live in `exit_codes.hpp`. | SRS SR-06, SR-AUTH-04, ER-05, EC-17 |
| D33 | Signal handling | No async signal handler. `SignalWatcher` blocks SIGINT/SIGTERM in the main thread before any other thread starts (so all threads inherit the block) and one watcher thread takes them with `sigtimedwait` (50 ms timeout, so its destructor returns quickly). First signal: `info: stopping... writing results` and `Pipeline::request_stop()`; a signal before the pipeline exists is remembered and stops the run as soon as it starts. Second signal (any mix of SIGINT/SIGTERM): `error: forced exit, results may be incomplete` and `_exit(130)`. Messages use raw `write(2)` on the watcher thread. The watcher lives until the result files are written. Two identical signals sent before the first is taken merge into one (POSIX), which a human Ctrl+C never does. | SRS FR-CLI-06, EC-08..EC-11, PR-06; UIUX 7.1 |
| D34 | TSan exit pause in signal tests | The signal tests start the child with `atexit_sleep_ms=0` added to `TSAN_OPTIONS`: TSan otherwise sleeps 1 s at exit while threads still run, which only a forced `_exit(130)` does, and that broke the 1 s latency check. The rest of the TSan suite keeps the default. | SRS PR-06 |
| D35 | Console summary | S4 is printed to stdout after the result files are written; warnings follow on stderr as `frameflow: warning: <message>` (ER-07 wins over UIUX S4's "between the result block and the file line": they appear there in a terminal because stdout is flushed first), then the `Files` line or the error. Frame counts (produced, delivered, dropped, in-flight, per-reason drops) cover the whole run so BR-01 is visible; latency, FPS, drop % and depth are after warm-up (D19), and a note line says so when warm-up > 0. A missing value prints `—`. No `Adaptive` row until the adaptive policy exists. Warnings: source's own lateness (D38) > 5 ms on > 1% of all produced frames; stopped during warm-up (`valid=false` without an error); warm-up > half the configured run; actual run (`t_end - t0`) shorter than 10 s. | SRS FR-MET-06, ER-07; UIUX S4, 9.3, 9.4 |
| D36 | Output FPS | Fix of P2.4: `output_fps` = frames whose `t_out` is inside `[t0 + warmup, t_end)` / `window_s`, a delivery rate (SPEC 10 "delivered / measured duration"). Before, it counted only frames *captured* in the window, so frames still queued at the end lowered it by about queue depth / window (seen: 18.3 instead of about 20 fps at a 50 ms cost). `window_delivered` keeps its meaning (captured in the window and delivered: the latency set). `input_fps` stays by `t_cap`. | SPEC 10; D19 |
| D37 | Phase 2 integration tests | Overload tests use 2 s runs at 50 fps with a queue of 4: at 2.0x (40 ms cost) dropping policies must drop 40-60% after warm-up; at 10x (EC-03, 200 ms) 80-97%. Blocking is checked with a hard lower bound instead of a timing: frame k cannot finish before `t0 + (k+1) x cost` and was scheduled at `t0 + k x interval`, so `latency_k >= (k+1) x cost - k x interval` (linear growth). "Bounded" for dropping is relative: max latency below half of blocking's, and the last third's mean latency not above 1.5x the first third's. The SR-04 stress run is 3 x 20 s (one per policy, BR-08) at 2.0x with a queue of 1, label `stress`. PR-10 is a `timing` test (release only, D9) on a synthetic 1800-frame report. CI runs one 3 s CLI smoke run per policy in every matrix preset. | SRS EC-03, SR-04, PR-10; SPEC 16 Phase 2 gate |
| D38 | Lateness vs backpressure | Fix of the D35 lateness warning, which fired on about 91% of frames for blocking at 1.5x. Lateness is measured before the push, but under blocking the source spends time inside the push of frame k-1 while the release times of frames k, k+1, ... pass, so *later* frames are late (excluding frames whose own push blocked would not help). `FrameMeta::backpressure` is the share of `source_lateness` caused by earlier push waits: the source adds each push's duration to a pending total, and at every release the share is `min(pending, lateness)`, after which pending is capped to that share, so waiting the source has caught up on is forgotten and cannot hide later slowness. The ER-07 warning uses `own_lateness() = source_lateness - backpressure`; the message is unchanged because it now only fires when the source itself is slow. `frames.csv` `lateness_us` stays the total (DR-01 fixes the columns); `backpressure` is kept in memory only. | SRS ER-07, EC-12, FR-SRC-07, DR-01; D35 |

## Testing and sanitizers

**Why the tsan preset runs tests under `setarch -R`.** GCC 13's TSan runtime crashes at
startup on recent kernels with high ASLR entropy (`vm.mmap_rnd_bits`); even an empty `main()`
segfaults. The tsan preset sets `CMAKE_CROSSCOMPILING_EMULATOR` to `setarch;-R`, so ctest and
`gtest_discover_tests` run test binaries with ASLR disabled for that process only. No system
setting is changed. Alternatives: `sudo sysctl vm.mmap_rnd_bits=28` (machine-wide), or a
newer toolchain whose TSan runtime handles the higher entropy.

**Why `tsan.supp` suppresses only libtbb.** OpenCV uses TBB as its parallel backend. TBB is
not built with TSan, so TSan cannot see its internal synchronization and reports false races
inside it (seen in the OpenCV `GaussianBlur` smoke test). `called_from_lib:libtbb.so` ignores
only calls made from inside TBB. Nothing in FrameFlow code is suppressed. Cost: a real race
whose accesses happen inside TBB (e.g. freeing a `cv::Mat` while OpenCV still reads it on a
pool thread) would also be hidden, so ASan runs and clear frame ownership still matter.

**Deliberate-race check.** A temporary test had two `std::thread`s increment a plain `int`
captured by reference. The tsan preset reported `ThreadSanitizer: data race` with both stacks
at the `++counter` line, and `halt_on_error=1` made the test fail. After the test was removed
the suite passed again. This proved that races in our own code are still detected with
`tsan.supp` loaded, and that a race fails CI instead of only printing a warning. The test was
not kept.

**Limitation: TSan only sees executed paths.** It checks the happens-before order of accesses
that actually run, so it does not depend on lucky timing, but a race on a path no test
executes (e.g. shutdown while the queue is full, pop timeout) is invisible. Concurrency tests
must therefore exercise shutdown, timeout and overload paths, not just the happy path.
